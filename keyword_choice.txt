3.2 Search Strategy and Keyword Formulation
To identify forum discussions related to JNI design smells, we employed a systematic keyword formulation strategy to ensure high recall and precision, mitigating threats to construct validity (Zhang et al., 2011). Our keyword list was constructed through a three-phase iterative process:
Phase 1: Seed Keyword Extraction. We first derived a baseline set of "seed keywords" directly from our proposed JNI Design Smell Catalog. This ensured our search was grounded in established theoretical concepts (e.g., Local Reference Table Overflow, Global Reference Hoarding).
Phase 2: Developer Vernacular Expansion. Prior research indicates a significant lexical gap between formal software engineering taxonomies and the colloquial language developers use on crowdsourced platforms like Stack Overflow (Barua et al., 2014). To address this, we expanded our seed keywords using developer-friendly synonyms, error codes, and specific API method names (e.g., expanding Global Reference Hoarding to include "global reference table overflow" and "NewGlobalRef").
Phase 3: Iterative Pilot Refinement. Following established guidelines for mining software repositories (Kitchenham & Charters, 2007), we conducted iterative pilot searches. Keywords that yielded excessive false positives (e.g., generic terms like "API") were constrained using client-side tag filtering to ensure JNI context. Conversely, academic terms that yielded zero results (e.g., "JNI MonitorEnter deadlock") were retained in the search string to ensure theoretical saturation, while their colloquial equivalents (e.g., "JNI synchronization deadlock") were added to capture the actual forum discussions.
This process resulted in a final, comprehensive taxonomy of 184 keywords, categorized across 17 functional domains (e.g., Memory Management, Threading, Data Type Conversion), ensuring comprehensive coverage of the JNI ecosystem.
